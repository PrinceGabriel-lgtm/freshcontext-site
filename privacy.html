FreshContext Privacy

This page explains the public FreshContext site, demo, MCP tools, hosted Worker surfaces, data sources, metadata, and contact expectations.

Last reviewed: 13 September 2026.

Scope

The FreshContext public site and demo are informational. They explain a freshness-aware context integrity layer for AI systems and show illustrative examples.

FreshContext provides context freshness, confidence, utility, and provenance metadata. It does not determine truth, provide professional advice, or replace domain review.

FreshContext is not legal, medical, tax, or financial advice.

Data Sources

FreshContext MCP tools and reference adapters may contact third-party public data sources depending on the tool used. Examples include public web pages, package registries, public APIs, and market or research data sources documented by the relevant adapter or page.

Users should review the source, timestamp, retrieved time, confidence, freshness score, and provenance fields before relying on any result.

Hosted Worker And Cloudflare

Hosted FreshContext Worker routes may be processed by Cloudflare infrastructure. Cloudflare logs or observability systems may contain request metadata such as route, timing, status, source network metadata, user agent, or error details.

Where implemented, KV, D1, or cache layers may store adapter results, feed records, cache metadata, operational metadata, or historical signal data.

The verdict ledger is narrower than that, and deliberately so. A stored verdict row holds identifiers, the source URL and source type, the decision and its label, the profiles applied, timestamps, the engine version, the signing payload and its signature — and a SHA-256 of the canonicalised content. It does not hold the content itself. Content is hashed before it enters the signed payload, which is what lets a verdict be verified without the material it was computed over ever being retained.

Metadata FreshContext Emits

FreshContext may emit metadata such as source URL, published time, retrieved time, freshness confidence, freshness score, utility values, status, provenance fields, and adapter details where applicable.

Verdicts written to the hosted ledger are signed. Current records use FRESHCONTEXT_HA_PRI_V4, an Ed25519 signature over the verdict-bound fields. The public key is published at /.well-known/freshcontext-signing-keys.json, so a third party can verify a verdict offline without a FreshContext account, an API key, or any contact with us. Records written before Ed25519 verify through the earlier HMAC path and report that they did, rather than being presented as equivalent.

Ha-Pri v1 is a different and older mechanism, used by the signal-intelligence path rather than by verdict attestation. Its salt is a published constant, so it should be treated as a provenance stamp and audit reference only. It is not authentication and not enforcement against alteration. The two should not be read as the same guarantee.

Local MCP And Core Usage

Local MCP/Core usage may run on your machine depending on setup. In local configurations, your own environment, MCP client, terminal, logs, and selected adapters determine what is fetched, displayed, or stored locally.

Do not paste secrets, tokens, private logs, customer data, or account credentials into public chats, GitHub issues, demos, screenshots, or logs.

User Data And Telemetry

FreshContext does not sell user data.

The public site does not include a payment flow. If telemetry, accounts, billing, or hosted product features are added later, this page should be updated before release.

Retention And Deletion

Stated plainly, because the honest answer is more useful than a tidy one: there is currently no automated retention limit and no scheduled deletion. Verdict rows and stored signal records persist until removed by hand. Cache entries in KV expire on a per-adapter timer measured in minutes to hours, but that is caching behaviour and should not be read as a retention policy.

Adding a retention window is open work rather than an implemented control. This page will say so when that changes, and it should not be read as promising one today.

To ask about removal of a specific record, use the contact page with enough detail to identify it, such as a verdict identifier or source URL. Requests are handled by a person, not a workflow.

Operator Profile Record

The hosted database holds one scoring-preference record used by the signal-intelligence and briefing paths to rank signals. It stores interests, skills, and a location, and it describes the operator of this deployment rather than any visitor or caller. It is seeded by hand; no automated path writes it, and the software falls back to a built-in default when it is absent.

It is described here because a complete account of what the deployment stores is more useful than one that covers only the parts that are easy to explain.
